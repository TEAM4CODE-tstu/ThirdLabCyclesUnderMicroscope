# Лабораторная работа №3 — «Циклы под микроскопом»: инварианты, вариант-функции и тотальная корректность

## Что это?
Данное приложение представляет собой интерактивную систему для **верификации циклических алгоритмов** на основе исчисления Дейкстры и логики Хоара. Проект является логическим продолжением линий ЛР-1 («Контракты») и ЛР-2 («Движок wp»), перенося методы формального анализа с линейных фрагментов на конструкции вида `init; while (B) { S }`.

На основе заданных инварианта и постусловия приложение автоматически:
* Вычисляет и визуализирует **слабейшее предусловие тела цикла (wp)** с переиспользованием движка из ЛР-2;
* Контролирует **монотонное убывание вариант-функции** для доказательства завершения (терминации);
* Проверяет сохранение инварианта на каждом шаге выполнения через `Debug.Assert`;
* Формирует полное доказательство **тотальной корректности** в четыре этапа (Инициализация, Сохранение, Выход, Завершение).

## Описание
В качестве сквозного сюжета для бизнес-логики сохранен модуль **«Логистика и учет грузов»**. В рамках данной лабораторной работы реализованы три режима обработки массива весов, каждый из которых имеет строгую математическую спецификацию:
* **PrefixSum** — вычисление суммы префикса массива (накопительный итог массы партии).
* **Count > T** — подсчёт количества грузов, превышающих пороговый вес T (фильтрация негабарита).
* **PrefixMax** — поиск максимального веса в текущем префиксе (контроль критической нагрузки).

Если в предыдущих работах анализ был полностью статическим или динамическим по отдельности, то здесь применяется **гибридный подход**: формальные условия корректности проверяются математически (через `WpEngine`), а их выполнение отслеживается визуально в реальном времени при пошаговом исполнении цикла. Это позволяет буквально «увидеть», как работает теория верификации программ.

## Архитектура проекта и описание классов
Приложение спроектировано по принципам чистой архитектуры с четким разделением ответственности между слоем доменной логики верификации и слоем представления по паттерну **MVVM**. Для реализации требований ЛР-3 были добавлены следующие ключевые компоненты:

### 1. Слой доменной логики верификации (`DomainClassLibrary/Domain`)
Содержит изолированные от интерфейса классы для описания режимов циклов и их пошаговой проверки:
* **`CycleModeInfo.cs`** — доменная модель, описывающая полный контракт одного режима цикла. Хранит не только делегат логики вычисления (`Func`), но и все формальные спецификации: предусловие ($P$), инвариант ($Inv$), условие цикла ($B$), тело цикла ($S$), вариант-функцию ($t$) и постусловие ($Post$).
* **`CyclePresets.cs`** — статическая фабрика пресетов. Централизованно возвращает список из трёх обязательных режимов (`PrefixSum`, `Count > T`, `PrefixMax`) с заранее определёнными математическими формулами и их текстовыми расшифровками на русском языке.
* **`CycleVerifier.cs`** — ядро алгоритма ЛР-3. Отвечает за пошаговое исполнение цикла. В конструкторе вызывает движок `WpEngine` из ЛР-2 для автоматического расчёта `wp(S, Inv)`. Метод `ExecuteStep()` выполняет одну итерацию, проверяет истинность инварианта до и после шага, контролирует убывание вариант-функции и содержит `Debug.Assert` для отлова нарушений корректности во время отладки.
* **`CycleStepResult.cs`** — DTO (объект передачи данных), возвращаемый верификатором после каждого шага. Содержит текущие значения индекса $j$ и результата $res$, флаги истинности инварианта, значение вариант-функции и флаг её убывания для синхронизации состояния UI.

### 2. Слой интерфейса и связывания (`GoodsLogistics`)
Реализует графическое отображение процесса верификации и управление состоянием:
* **`ArrayItemViewModel.cs`** — обёртка над элементом массива для отображения в таблице. Содержит числовое значение (`Value`) и флаг подсветки текущего индекса (`IsHighlighted`). Переопределяет метод `ToString()`, чтобы WPF корректно отображал числа в ячейках даже при сложной привязке данных.
* **`CycleViewModel.cs`** — главная ViewModel третьей вкладки. Управляет генерацией массива, переключением режимов и навигацией по шагам цикла. Формирует строки с четырьмя условиями корректности и текстом wp-анализа. Реализует команды `StepCommand`, `RunCommand`, `ResetCommand` и `GenerateCommand`.
* **`HighlightToColorConverter.cs`** — конвертер значений для XAML (расположен в `Infrastructure`). Преобразует булево свойство `IsHighlighted` в цвет фона ячейки таблицы (белый или светло-желтый `#FFFACD`), позволяя реализовать подсветку текущего индекса $j$ средствами чистого WPF.
* **`CycleView.xaml`** — пользовательское представление (`UserControl`) для визуализации ЛР-3. Содержит панель генератора массива, редактируемую таблицу данных через `ItemsControl` с `DataTrigger` для подсветки, два эллипса-индикатора инварианта (до/после шага), прогресс-бар вариант-функции, блоки вывода wp-анализа и условий корректности.

## Использованные технологии
* **Платформа:** .NET 8 
* **Язык программирования:** C# 12
* **Графическая подсистема:** Windows Presentation Foundation (WPF) 
* **Архитектурный паттерн:** MVVM (Model-View-ViewModel) 
* **Формальные методы:** Исчисление слабейших предусловий Дейкстры, инварианты циклов, вариант-функции

## Как пользоваться приложением
1.  **Переключение на вкладку циклов:** В верхнем меню приложения перейдите на вкладку **«Циклы: Инварианты»**.
2.  **Выбор режима:** В левой панели выберите один из трёх режимов в выпадающем списке «Режим цикла» (PrefixSum, Count > T, PrefixMax). Для режима Count > T задайте порог T.
3.  **Генерация или ввод данных:** Используйте блок «Генератор массива» для создания случайного массива или введите элементы вручную в поле «Массив (через запятую)».
4.  **Пошаговая симуляция:** Нажмите кнопку **«Шаг»** для выполнения одной итерации цикла. Наблюдайте за:
    *   Подсветкой текущего элемента `j` жёлтым цветом;
    *   Индикаторами истинности инварианта (зелёный/красный) до и после шага;
    *   Прогресс-баром вариант-функции (должен монотонно убывать).
5.  **Автоматическое исполнение:** Нажмите **«Пуск (Авто)»** для выполнения всего цикла до завершения. После остановки проверьте индикатор постусловия.
6.  **Анализ wp-сохранения:** В блоке «Проверка сохранения (wp)» отображается автоматически сгенерированная формула `wp(S, Inv')` с разбором на русском языке. Значение вычисляется переиспользованным движком из ЛР-2.
7.  **Сброс:** Кнопка **«Сброс»** возвращает симуляцию к начальному состоянию. Изменение порога T также автоматически сбрасывает симуляцию.
